# DearDairy 🌙

> 一个关于长期自我理解的 AI 日记概念：日记是证据，AI 的解析只是推测，而用户保留对“我是谁”的最终决定权。

**项目状态：保留想法，停止主动产品开发。** DearDairy 不是准备商业化或大规模推广的产品。这个网站已经成为一个可以交互的作品，用来完整表达我希望 AI 日记成为的样子。

## 直接体验

### 作品 Demo：无需账号或设置

- **[中文 Demo](https://deardairy-phi.vercel.app/cn/demo)**
- **[English Demo](https://deardairy-phi.vercel.app/demo)**

Demo 内含 20 篇虚构日记，并会根据访问当天动态调整日期，让这些记录始终像是发生在“今天之前”。其中可以体验日常记录、周回顾、月回顾、近期观察、长期 Persona，以及对观察进行确认、修改或拒绝的完整流程。内容是预先写好的，但页面可以真实交互。

### 作为私人本地日记使用

- **[中文本地日记](https://deardairy-phi.vercel.app/cn/journal)**
- **[English local journal](https://deardairy-phi.vercel.app/journal)**

无需账号和数据库。日记保存在当前浏览器。用户也可以选择提供仅保留在当前会话中的 API Key，连接 DeepSeek、OpenAI、Groq 或 OpenRouter，并根据最近最多 12 篇日记生成私人回顾。

这里的“本地”指浏览器本地存储：清除浏览器数据，或者更换浏览器、设备后，日记不会自动同步。备份导出和导入仍属于之后真实使用时需要补充的功能。

## 我真正想保留的想法

DearDairy 最重要的从来不是“在网页上写日记”，而是探索一个更具体的问题：

> AI 能否从一个人的长期日记中识别反复出现的模式，帮助其维护一份持续变化的人格描述，同时不夺走本人对这份描述的决定权？

人不仅渴望表达，也渴望被理解、被读懂、被解析。普通日记保存表达，却不会回应；普通 AI 对话可以即时回应，却不一定能清楚呈现一个人几个月或几年间的变化。DearDairy 想探索的是这两者之间的空间。

## Persona 应该如何生长

```text
可选的初始问卷 → 第一版 Persona
长期日记 → AI 提出近期观察
用户确认、修改或拒绝每条观察
反复出现且经过确认的观察 → 持续变化的长期 Persona
```

整个产品最重要的原则是：

> **日记是证据，AI 的解析只是推测。**

系统需要区分原始表达、近期观察、稳定模式候选，以及用户确认的人格描述。AI 可以帮助一个人发现自己没有注意到的部分，但不能把一次解析悄悄变成关于这个人的事实。

因此，用户需要能够：

- 查看一条观察基于哪些日记；
- 确认它确实符合自己；
- 修改措辞，直到它足够准确；
- 拒绝它，并且不产生负面后果；
- 只允许经过确认且反复出现的观察进入长期 Persona。

## 反思不应该成为自我惩罚

日记之后可以有一个温和的问题，但它不应该把反思变成绩效管理。它不应该因为用户某天没有产出而制造羞耻，也不应该为了连续打卡而牺牲真实表达，更不应该强迫用户得出积极结论。

一个好的问题应该与刚刚写下的内容有关，允许不回答，并帮助用户注意某种情绪、动机、矛盾或反复出现的模式。当用户已经很低落时，系统应该先留出承接的空间，而不是要求其继续深入分析自己。

## 为什么它会停留在原型阶段

网站只是当时最容易实现的载体，并不一定是最适合写日记的形态。相比手机 App、备忘录或直接与 AI 对话，网页会给一个本就依赖长期习惯的行为增加额外门槛。

我也不认为这种形式具有清晰的盈利路径或大规模使用可能。继续堆叠功能并不能解决这个根本错位。因此，DearDairy 的价值不是证明这个网站应该成为一门生意，而是让一个产品观点变得可见：AI 可以进行长期解析，但解析必须可解释、可修改，并由被描述的人掌握最终决定权。

停止开发并不是否定这个想法，而是把“值得保存的观点”和“需要无限维护的网站”分开。

## 隐私与当前架构

公开 Demo 全部使用虚构内容，不依赖用户数据。私人日记模式使用浏览器本地存储，不依赖 Supabase 或其他用户数据库。

如果用户主动启用 AI：

- API Key 只保留在当前浏览器会话；
- 只有用户要求生成回顾时，所选日记文字才会被发送；
- 请求由无状态 Vercel Function 转发给用户选择的服务商；
- DearDairy 不会把 Key、请求或回答写入数据库；
- 可访问的 API 服务地址受到明确限制，不会成为任意网络代理。

当前展示版本使用 React、Vite 和 Vercel。仓库中仍保留早期基于 FastAPI、PostgreSQL 和账号系统的原型，作为历史实现材料；现在发布的本地日记不依赖它。
